Findings-to-Fix

From AI triage verdict to a reviewed fix in the editor

cx-findings-to-fix is a Claude Code plugin, used from the terminal or through the Claude Code VS Code and JetBrains extensions. Scans run from the customer's CI/CD pipeline against the code in Bitbucket, and Triage Assist evaluates the critical and high findings using Attackability-based context (reachability, exploitability, code context, policy signals), updating the state of findings that require action to Confirmed and theoretical ones to Proposed Not Exploitable. The plugin starts from that verdict: the /cx-findings-to-fix:fix command, a subagent and a skill carrying the same protocol, and one small tool (ftf, shipped in Python and Node) that calls the Checkmarx One REST API and brings each fix into the editor as a change the developer accepts or rejects. Three zones, one path from the tool to the Checkmarx One REST API, and an API key Claude never holds. A GitHub Copilot version of this plugin exists as a separate repository.

    Credential boundary

    Claude orchestrates the run and never holds the Checkmarx credential. The ftf tool reads the API key from the shell profile or the cx CLI configuration, exchanges it for a short-lived token it holds in memory, and calls the Checkmarx One REST API with that token. The API key never appears in Claude's conversation.

    The Claude Code session lives in Claude Code's own sign-in and never reaches Checkmarx. The credential that triggers scans stays in the CI/CD system and never reaches the developer's machine.

    What the plugin cannot do

    The plugin reads findings and fetches fixes. It cannot change a finding's state, trigger a scan, or touch Checkmarx configuration. Triage Assist owns the verdicts: it evaluates eligible findings for Attackability on the platform, updates the state of findings that require action to Confirmed and theoretical ones to Proposed Not Exploitable, and leaves previously triaged findings unchanged.

    Every change to code arrives as an edit the developer accepts or rejects. The tool writes nothing into the project on its own during the normal flow, and the plugin never commits or pushes. Only Confirmed critical and high findings are considered. Package (SCA) fixes are supported and off by default.

    Distribution

    The plugin lives in a Git repository developers can reach: Bitbucket, GitHub, or an internal Git server. Each developer runs two commands once, claude plugin marketplace add with that repository and claude plugin install with the plugin from it. Claude Code's managed settings can pre-approve the marketplace for everyone in the organisation.

    Per developer, one time: an API key, and Python 3 or Node on the machine. Claude Code's Bash tool must be allowed, which is how the plugin runs, and the first run asks the developer to permit the plugin's command. Nothing runs on a server and nothing is installed besides the plugin folder.
